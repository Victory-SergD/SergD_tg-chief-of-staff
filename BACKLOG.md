## TRACK 1: Q&A Бот для ежедневной работы с вопросами

**Создан:** 2026-05-08
**Приоритет:** HIGH (после стабилизации текущей схемы)
**Зависит от:** ~1-2 недели наблюдения за текущим workflow с файлами

### Видение

Сейчас Сергей отвечает на critical-вопросы через файл `critical_for_sergei.md`.
Anastasya — через файл `critical_for_anastasya.md` (или `assistant_bot.py`).
Подчинённые — через личку (`ask_subordinates.py`) с парсингом ответов.

**Проблема:** файлы — разовая выгрузка. Если Сергей ответил на 50 из 123 — остаются 73 + новые с следующего daily.sh. Файл становится хаотичным.

**Цель:** Сделать ежедневный поток вопросов через `assistant_bot.py` (на токене Pixel Bot):

#### Workflow для Сергея
- Утром бот шлёт ему: «У тебя 5 новых HIGH-вопросов» (с контекстом и формулировкой)
- В течение дня в любой момент: голосовое или текст с ответом → бот распознаёт → пишет в БД + user_notes
- Команды: `/today`, `/pending`, `/skip #ID` (пометить как «не отвечу, уберите»)
- Если вопрос уже задавался и Сергей ответил — больше не повторяется

#### Workflow для Anastasya (тот же бот, тот же механизм — уже есть в `assistant_bot.py`)
- /today → текущий список её critical
- голосовое → парсинг → запись

#### Workflow для подчинённых (через Telethon-личку, как сейчас)
- Уже работает через `ask_subordinates.py` → `collect_subordinate_answers.py` в daily.sh
- Reminder через 48ч → `remind_subordinates.py`

### Что нужно сделать

1. **Расширить assistant_bot.py:**
   - Команда `/today` для Сергея — выгружает текущие critical_for_sergei (HIGH сначала)
   - Голосовое от Сергея → транскрипция через Telegram Premium → парсинг через Opus → запись
   - Команда `/skip #ID комментарий` — пометить вопрос как irrelevant с причиной
   - Команда `/owner #ID @username` — переадресовать вопрос подчинённому/Anastasya

2. **Voice transcription в боте:**
   - Сейчас бот не парсит голосовые
   - Нужно: получает voice → скачивает → Telegram Premium TranscribeAudio (есть в collector.py) → текст → handle как текстовое

3. **Интеллектуальная компоновка контекста:**
   - Когда бот шлёт вопрос — давать большой контекст: о ком вопрос, что в user_notes, последние 5 сообщений по теме
   - Использовать Opus для адаптации формулировки к конкретному моменту

4. **Дедупликация по дням:**
   - Если Сергей уже скипнул вопрос — не возвращать его (даже если Опус снова сгенерирует похожий)
   - Хранить `skipped_questions` таблицу: qid + reason + skipped_by + skipped_at

5. **Daily routine для Сергея:**
   - Сценарий: 7:00 — бриф в TG. 8:00 — список вопросов на сегодня (3-5 high). По мере дня — голосовые ответы. 22:00 — итог сколько закрыли.

6. **Push-вопросов от Сергея вручную:**
   - Команда `/ask @username вопрос` — Сергей сам формирует вопрос подчинённому через бота
   - Бот шлёт через Telethon, трекинг как обычная outbound

### Что нужно от Сергея перед стартом

⚠️ **Перестроение структуры команды:**
   Сергей даст точный список:
   - Кто его прямой подчинённый
   - Какие ветки/проекты за каждым
   - Кто peer / partner / client / boss
   - Какие алиасы для Опуса (типа `cody → ajdkdow`)

После этого — переклассификация всех disputed_questions.answer_owner на основе свежей структуры.

### Метрика успеха

- Сергей отвечает на 80%+ HIGH-вопросов в день получения (сейчас файл может висеть несколько дней)
- Anastasya закрывает 90%+ её вопросов в течение 24ч
- Время от вопроса до ответа в среднем <12 часов
